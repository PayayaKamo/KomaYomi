# 画像の前処理と名前変更

KomaYomi は指定したフォルダの画像をその場で読み込みます。コピーも変換もしません。改名や分割は、前処理ダイアログで明示的に操作したときだけ行います。だからこそ、巻を追加する前の数分の整理が、コマ検出・ページの対応づけ・比較リーディングの出来を決めます。少し面倒でも、同じページを3言語で3回直すよりは安上がりです。

## この工程で解決すること

自動分割はきれいなスキャン向けに調整されています。ページが傾いている、スキャナの黒枠が残っている、AVIF/HEIC が混ざっている、あるいはどれか一つの言語でページが 1 枚足りない—そうした状態でもライブラリは開けますが、対応づけ、位置合わせ、ノート、エクスポートという後工程すべてがその問題を引き継ぎます。一度整理しておけば、同じページを 3 言語で 3 回直す手間がなくなります。

## ファイルの扱われ方

| 動作 | 影響 |
| --- | --- |
| 指定したフォルダから直接読み込みます。 | 取り込みも複製もしません。編集は `data/` にだけ書き込まれます。改名・分割は前処理ダイアログで操作したときだけ実行されます。 |
| ページは**並び順**で対応づけます。ファイル名ではありません。 | 改名すると順番が変わります。途中に 1 枚挿すと、以降のページがすべてずれます。 |
| 並びは自然順です。連続する数字は数値として比較します。 | ゼロ埋めがなくても `2.jpg` は `10.jpg` より前に来ます。 |
| WebP は検出・分割に対応します。AVIF、HEIC、GIF、BMP はデコードされません。 | **自動分割**を使うなら AVIF/HEIC/GIF/BMP を JPEG か PNG に変換してください。WebP はそのままで検出でき、分割結果は PNG になります。 |
| 1 枚の画像が 1 ページです。 | 見開きは 1 ファイルのままにするか、前処理で全言語を同時に分割してください。 |

## 整理のチェックリスト

原本を残したいなら、コピーのほうで作業してください。どのツールを使うかより、次の順番のほうが重要です。

1. **回転と傾き補正。** 読み方向はページごとに保存されますが、横倒しのスキャンを比較リーディングで直すことはできません。
2. **スキャナの黒枠と見開きの影を切る。** ページ端がまっすぐだと、端に接するコマも検出されやすくなります。
3. **自動分割を使うなら AVIF / HEIC / GIF / BMP を JPEG / PNG に変換。** WebP はそのまま使えます。セリフが読める画質は保ってください。
4. **1 話 1 フォルダ。** 1 つのディレクトリに 2 話を混ぜないでください。話はコマテンプレート、位置合わせプリセット、エクスポートの単位です。
5. **本文でない画像を除く。** 表紙、奥付、カラーページ、他の版に存在しない特典画像などです。これらは以降のページをすべてずらします。
6. **見開きは分割しないか、全版を同じ位置で分割する。** 見開きは 1 ページとして数えます。日本語版だけ分割して中国語版を分割しないと、日本語の 12 ページ目が中国語の 12–13 ページ目になり、対応が崩れます。前処理の**分割…**なら全言語を一度に切れます。
7. **ファイル名は必要なら整える。** ゼロ埋め（`001.jpg`）は差分確認や目視に便利ですが、スキャナは並び順と自然順を見るので `1.jpg` でも `001.jpg` でも動きます。前処理の**ファイル名を変更**は話全体を振り直し、保存済みのページデータも一緒に移します。

## KomaYomi 内での改名と分割

**前処理…** を開き、巻を選びます。巻・話の表示名、ページ順、除外、ページの役割に加えて、各話のセクションに**ディスク上のファイル**があり、実際のファイル操作が 2 つ用意されています。画像形式の変換は引き続きアプリの対象外です。

**一括改名。** 接頭辞、開始番号、桁数を入れて**ファイル名を変更**を押します。ボタンの上に表示されているページ順（矢印で並べ替えた順）で振り直し、ディスク上のファイルを実際に改名します（`001.jpg`、`002.jpg`…。拡張子はそのまま）。その話で全ページがそろっている言語はまとめて改名されるので、各言語の *n* ページ目は同じ絵のままです。ページが欠けている言語は変更せず、結果に一覧で表示します。

ページデータ、履歴、除外、ページの役割、保存済みのページ順はページ番号で管理されているため、同じトランザクションで移動し、参照を書き換えます。アプリ内の改名で注釈・メモ・コマ編集が孤立することはありません。改名後は巻を再読み込みするので、他の編集は先に適用してください（未保存の下書きは破棄されます）。

何かを動かす前に `data/file-ops/` へマニフェストを書き、変更前と変更後の名前をすべて記録します。途中で失敗するとバッチ全体を元に戻し、マニフェストを `rolled-back` にしてフォルダを元の状態に戻します。既に別のファイルが使っている名前は上書きせず、エラーで拒否します。

**ページを分割。** ページの下の**分割…**を押し、見開きなら**左右**、それ以外は**上下**を選び、分割位置をパーセントで指定して確定します。画像は `<名前>-a` と `<名前>-b` に切られ、後半が次のページになり、以降のページが 1 つずつずれます。そのページを持つすべての言語を同じ位置で切るので、対応は崩れません。分割は PNG / JPEG / WebP に対応し、WebP は PNG として出力されます。GIF・BMP は拒否します。元画像は削除前に `data/file-ops/` へコピーされます。

元のページ文書は両方の半分に切り分けられます。半分に掛かるコマと注釈はその半分に残して座標を再計算し、コマ単位のメモはコマに追従、ページ単位のメモは前半に残ります。両方の半分は元ページの読み方向を引き継ぎます。分割後は、特にコマを横切った場合に両ページを確認してください。

::: warning 改名と分割はダイアログから取り消せません
**前回の適用を復元**は `library.json` だけを戻します。改名と分割は UI では一方向です。元の名前や画像が必要なときは `data/file-ops/` のマニフェストとバックアップを使ってください。アプリ外での改名は引き続き安全ではありません。ページデータはページ番号で管理されるため、ファイルマネージャーやシェルでの改名では注釈が移動しません。
:::

## 注釈を始める前の確認

1. 巻を追加し、サイドバーで開きます。
2. 巻と話の行に出る警告を読みます。*言語間でページ数が違う* と *ファイル名がページ順と一致しない* は、整理ミスのサインです。
3. フォルダ構成が特殊なら、**フォルダ検出の規則…** を開き、プレビューで確認してから保存します。[フォルダ検出の規則](/ja/guide/folder-rules)を参照してください。
4. 最初、中央、最後のページを開き、同じコマに同じ絵が入っているか確かめます。ずれていれば、ページ数か見開きの扱いが間違っています。
5. ここまで確認してから**自動分割**を実行し、ノートを書き始めます。

## よくある落とし穴

- **1 つの言語だけ 1 ページ多い。** 表紙や奥付が余分なことが多いです。削除するか、他の言語にも同じページを足してください。
- **見開きが 1 版だけ分割されている。** 見開きはそのままにするか、全版を同じ位置で分割します。
- **AVIF / HEIC ページの自動分割がめちゃくちゃになる。** 形式を変換してください。検出は AVIF/HEIC/GIF/BMP をデコードしません。
- **アプリ外で改名したらノートが次のページに移った。** ページデータは番号で管理され、ファイルマネージャーやシェルの改名では移動しません。前処理の**ファイル名を変更**を使うか、注釈の前に改名してください。
- **分割位置がコマを横切った。** コマとコマの間を指定するか、分割後に両方の半分のコマを直してください。ページ単位のメモは仕様どおり前半に残ります。
- **ページは正常なのにサムネイルの形式が混在する。** サムネイルは拡張子ではなく中身に従います。実体が JPEG の `.png` も正しく表示されるので、見た目だけの問題です。
- **注釈のあとでフォルダを組み替えた。** 検出 ID が変わり、以前のページデータが見つかりません。フォルダ検出の規則は注釈の前に適用してください。
